# Template Decision: Astro Starlight

The visual system will no longer be designed through bespoke component adjustments. The migration branch adopts the official **Astro Starlight** documentation starter as its foundation. Starlight provides a finished, production-ready default interface: a responsive sidebar, documentation search, accessible typography, table of contents, and light/dark support. It is intentionally being used without custom visual overrides.

The choice is operational as well as aesthetic. The existing corpus is built from Markdown and MDX files generated by Python scripts, and Starlight accepts Markdown and MDX as first-class content. Its static build process also produces a Pagefind search index automatically, so the site gains a complete documentation search experience without additional search infrastructure.[1]

The migration is intentionally staged. The validated template branch contains a concise research entry point and six top-level pages that establish the information architecture: the research workbench, Family Code, Rules of Court, legislation, analysis, and people and institutions. The existing Fern site remains live and unchanged while the remaining generated statute, rule, and research pages are converted from Fern-specific MDX components into portable Markdown.

The next engineering phase is content migration rather than design. It will update the existing Python generators to target Starlight’s `src/content/docs/` directory, replace Fern-only cards and callouts with standard Markdown or Starlight-native components, and rebuild the bill catalog as an isolated interactive surface only after the source corpus is in place. This avoids a big-bang rewrite and preserves the current site as a reference until the replacement is complete.

> The default Starlight template is now the design decision. Future work should concentrate on authoritative sources, coverage, provenance, and retrieval—not visual tuning.
